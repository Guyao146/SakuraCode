# 项目任务、Git 审阅与知识版本

本文说明 **v1.1.5 本批的持久任务、Git 审阅与知识集合版本能力**，不代表代码／标签已推送、正式 Release 已发布或全部验证通过。发布工作流先创建 draft，核验附件、版本、发行说明和 SHA-256 后再正式发布；最终验证结果见 [v1.1.5 发行说明](releases/v1.1.5.md)。三个入口仅向当前工作区的本机操作员开放；远程部署的操作员、只读访客和手机分享不会因此获得任务管理、Git 审阅或知识版本管理权限。

## 持久任务：工作进度、命令证据、人工验收分开

工作台顶部的当前进度仍来自 `todo_write`。展开 **持久任务与验收** 后，可「新建任务」或「保存当前待办」，记录标题、说明、优先级、步骤、验收标准及所选检查命令。只有明确保存才建立持久任务卡，重启不会把旧卡自动变成当前待办或重新派发任务。

- **工作完成**是任务进度；**命令验证**记录实际执行结果；**人工验收**表示用户确认符合任务标准。三者独立，不能用模型输出“通过”代替进程证据，也不把命令退出码 0 自动当成人工接受。
- 「验收命令」先保存 `bash`／`pwsh`、命令、工作区内相对目录、超时及必选／可选属性。保存不运行；运行时逐项通过现有工具审批管道，仍受当前审批模式和规则约束。可选项可明确跳过，必选项不能跳过。
- 每次运行保留命令、开始／结束时间、退出状态及有界日志。失败、拒绝、超时或停止即结束本次序列，剩余命令不执行；**不自动重试或重放**。重启后的未完成记录明确标为中断，不把未知结果改成成功。再次运行必须由用户重新发起，模型请求的“失败自动重试”不重跑这些命令。
- 任务设为完成后才可人工验收；有必选检查时，当前任务／命令版本必须已有通过记录。说明或检查配置变化会使旧证据过期；可取得 Git 指纹时还检查受跟踪源码变化。未跟踪文件、子模块内部工作树和外部服务状态不在该指纹保证范围内，无法验证时不会宣称源码未变。
- 「继续」仅切换关联会话并准备草稿，不发送消息、不执行命令；关联会话缺失时保留任务。归档不删除历史；运行报告可下载为 Markdown，导出前自行审查命令和日志中的敏感内容。

默认上限为 128 张任务卡、32 个命令定义、每任务 12 个检查、128 次运行；账本最多 8 MiB，单项输出最多 32,000 字符并标记截断。满额会报错，不自动淘汰旧报告。验收命令本身可能修改文件或联网，**本机管理入口不等于命令沙箱**，执行前需核对其副作用。

## Git 审阅：原始字节，只读仓库

进入 **工作台 → 变更 → Git 审阅**，选择本地比较基准（默认 `HEAD`）并刷新：

| 范围 | 比较内容 |
| --- | --- |
| 未暂存 | 暂存区 → 工作树 |
| 已暂存 | HEAD → 暂存区 |
| 总差异 | 所选本地基准 → 工作树 |
| 未跟踪 | 未跟踪且未被 ignore 规则排除的路径；默认不读取正文 |

此入口独立于「工具记录」，后者只展示成功 `write`／`edit` 的历史。Git 审阅按仓库对象和工作树的**原始字节**比较，不运行 clean／smudge 过滤器、textconv、外部 diff 或 hooks，不进行换行归一化；结果可能与启用了这些转换的常规 Git 展示不同。Git 子进程使用隔离的临时元数据和配置，不刷新或改写真实 index，不 stage、commit、reset、apply，也不 fetch 缺失对象。仓库在工作区上级时只审阅当前工作区范围。

- 未跟踪项需逐个点击「明确读取此文件」，才读取安全的普通 UTF-8 文本；不会为补丁自动包含它们。忽略的未跟踪文件不列出，也不能通过输入路径绕过；**已跟踪文件不会仅因后来匹配 ignore 而从差异中消失**。
- 「标记已审阅」只记录这份内容指纹。内容或比较基准变化时需重新审阅，不视为自动验收。
- 只可从**同一个比较范围**选择已跟踪普通文本并导出完整 `.patch`。未跟踪、二进制、冲突、符号链接和子模块不导出，不用摘要或截断文本伪造补丁；下载后由用户自行决定是否应用或提交。
- 子模块只检查 gitlink／索引记录和可读的当前子模块 HEAD，**不遍历内部未提交改动**，内部 dirty 状态为未知，不宣称干净。符号链接只展示链接信息，不跟随目标读取。
- 默认最多 2,000 个受跟踪文件、2,000 个未跟踪路径、32 个明确选读项；单文件 2 MiB、累计内容 64 MiB、补丁 4 MiB、单次操作 30 秒。超限、状态变化或取消时明确失败，不输出冒充完整内容的裁剪补丁。缺 Git、无仓库或本地基准不可用时按提示处理，不自动修复仓库。

## 知识集合：手动登记、全量预览与历史引用

进入 **设置 → 工作区与记忆 → 本地知识库 → 集合与版本**。旧导入继续作为 `.sakura/knowledge/` 下独立批次使用，**不会自动迁移或合并**。明确选中批次并「登记版本管理」才成为集合 v1，原文件、路径和文档 ID 不变。

「导入新版本」需选择该集合的新版本**完整文件列表**，先查看新增、移出当前版、修改、未变，再「确认发布新版本」。未选入的旧文件不属于新当前版，但历史原文保留。默认列表／检索只包含活动版本和未纳管资料；旧 `documentId` 与原 SHA-256 引用仍读取原文，不跳到当前版本。「恢复为当前版本」只切换活动指针，先检查历史数据存在且未被外改。

预览只放在有界内存，取消不落盘；5 分钟过期，重启失效，每次确认尝试只使用一次。元数据 revision／fingerprint、基线版本或内容变化会拒绝旧确认，需重新预览。新内容先发布到独立受管目录，再原子切换清单；清单损坏、缺失或版本外改时安全失败，不把历史／未引用残留当作新资料检索。

默认容量按未纳管资料、全部历史及受管残留合计：128 个文件、单文件 256 KiB、总计 4 MiB；最多 32 个集合、64 个集合版本，不自动删除历史。删除损坏历史文件也不会释放其已登记配额。直接文本导入只支持 UTF-8 Markdown／TXT；v1.1.5 另提供文本型 PDF／DOCX 本地解析、预览确认后入库，原件与来源映射单独保留，不支持 OCR，见 [工作资料工具说明](workspace-data-tools.md)。无目录监听、自动更新、自动上传、网页抓取或向量服务；导入和切换本身不调用模型。用户正常发送引用或允许工具读取后，相关片段仍会进入所选模型请求。更多阅读和版本语义见 [本地记忆、知识库与模型选择](memory-knowledge-models.md)。

## 磁盘位置与不应提交的个人数据

以下均相对**当前工作区根目录**；不是源代码，也不要靠批量删除来解除版本冲突或清空锁。

| 路径 | 内容及提交边界 |
| --- | --- |
| `.sakura/tasks/state.json` | 任务、检查命令、验收记录和运行日志；可能包含私有路径、业务数据或命令输出，不应提交 |
| `.sakura/tasks/write.lock`、`.sakura/tasks/.tasks-*.tmp` | 并发锁和临时保存文件，不应提交；先确认无其他写入者再人工处理残留 |
| `.sakura/git-review/state.json` | 本工作区的已审阅指纹，不改变 Git index；个人审阅状态不应提交 |
| `.sakura/git-review/` 中的锁／临时文件 | 本机保存状态，不应提交；损坏时备份原文后明确修复，不自动覆盖 |
| `.sakura/knowledge/batch_<UUID>/…` | 旧批次原始资料；登记为 v1 后仍在原处，不应随代码默认提交 |
| `.sakura/knowledge-versions/manifest.json` | 集合历史、文件哈希和活动指针；与资料共同备份，不应独立提交或手改版本关系 |
| `.sakura/knowledge-versions/versions/<versionId>/…` | 受管版本原文，包含当前及历史私有资料，不应提交 |
| `.sakura/knowledge-versions/staging/`、`store.lock`、`.manifest-*.tmp` | 暂存、独占锁和临时清单；未引用内容不进入检索，不应提交 |
| `.sakura/sessions/`、`.sakura/workspace-memory.md` | 会话／附件和个人记忆；自定义会话目录也应同样保护，不应提交 |

Git 审阅还会在系统临时目录建立 `sakura-git-read-*` 隔离副本，操作结束清理；它可能短暂含有代码字节，不是用户应提交的输出。下载的验收报告和补丁写入浏览器选择的下载位置，不自动成为项目文件；分享或提交前先审查敏感内容。桌面个人配置、凭据密文、浏览器数据及日志位于 `%LOCALAPPDATA%\SakuraCode\Desktop`，也不属于项目提交内容。

本仓库已忽略 `.sakura/` 与 `tmp/`；其他工作区需自行核对忽略规则，以及是否已有敏感文件被跟踪。添加 ignore 不会撤回历史提交，审阅界面也不是秘密扫描器。需要团队共享命令或资料时，应另外整理经过审查的项目文件，勿直接提交整个个人账本或知识存储目录。

本机 API 分别为 `/api/tasks`、`/api/git-review`、`/api/knowledge/versions`，要求当前 `X-Sakura-Workspace`；变更操作还需明确确认和对应版本／快照凭据。页面切换工作区、登录失效或状态变化后，应刷新再确认，不重复发送旧操作。
