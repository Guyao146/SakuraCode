# SakuraCode v1.1.5

本批汇总两批此前本地未发布的增量：持久任务、Git 审阅与知识集合版本，以及文档入库、工作资料备份恢复、独立开发目录和外接接入向导。既有用户配置、会话、记忆、知识资料和项目文件不自动迁移或删除。

本文是 v1.1.5 的发行说明，不表示代码／标签已推送、GitHub 正式 Release 已发布或全部验证通过。发布工作流先创建 **draft Release**，核验附件、版本、发行说明和 SHA-256 后，再由维护者发布为正式 Release。

## 改进

- **持久任务与验收**：工作台可明确保存任务、步骤、验收标准和检查命令，重启后保留；与 `todo_write` 当前进度分开。工作完成、命令验证和人工确认是独立状态。命令逐项经过审批，记录真实进程退出状态／退出码、起止时间和有界日志；模型宣称“通过”不能替代执行证据，退出码 0 也不等于人工接受。失败、拒绝、超时或停止不会自动重跑，重启后的未完成运行标为中断；任务或命令变化使旧证据过期。
- **实际 Git 差异与审阅标记**：在「变更 → Git 审阅」查看未暂存、已暂存及所选本地基准的总差异；未跟踪文件需明确选读。比较原始字节，不运行过滤器、textconv、外部 diff 或 hooks。审阅标记绑定内容指纹，内容或基准变化需重新审阅。从同一范围选择已跟踪普通文本导出完整 `.patch`，不改真实 index，不自动 stage、apply、commit 或 push；不为未跟踪、二进制、冲突、符号链接或子模块伪造补丁。
- **知识集合版本**：旧批次明确登记后才纳管，不自动迁移或合并。新版本先预览完整文件列表的新增、移出、修改和未变，再确认发布；支持明确恢复历史版本为当前版本。检索默认只含当前活动版本及未纳管资料，旧文档 ID／SHA-256 仍指向原文。历史保留并计入配额，过期预览、并发变化或历史外改会拒绝确认。
- **本地文本型 PDF／DOCX 入库**：内嵌本地 parser 在受限 worker 中提取文本，选择页／段落并预览后确认入库；原件与来源映射（provenance）保存在 `.sakura/documents/`。PDF 使用物理页码，DOCX 使用段落／表格编号，不推算页码。不支持 OCR、加密 PDF、旧 DOC、宏或嵌入对象，不加载外部资源，不调用模型；复杂排版须人工核对，worker 不等于操作系统沙箱。
- **工作资料备份与恢复**：预览后导出会话、记忆、知识、任务及其依赖，逐文件附 SHA-256。不包含源码、Git 元数据、凭据存储、插件配置或连接器配置；聊天、附件和命令输出／日志仍可能含秘密，备份不是自动脱敏结果。恢复仅写入现有父目录下一个不存在的新目录，不覆盖原工作区、不自动打开或执行；恢复后的记忆默认关闭，任务验收只作历史，使用前阅读恢复报告并重新验证。
- **独立任务开发目录**：从本地已提交基准建立应用私有 Git common directory 下的真实 linked worktree，不共享原仓库的公共元数据，不改原仓库 HEAD／index。原工作区 dirty 内容、未跟踪文件和个人 `.sakura` 数据不复制；已提交的秘密仍可能随基准带入。每个任务使用独立 harness、会话、审批、验收和数据目录，启动须明确选择模型及任务；不自动加载仓库插件、hooks、MCP、连接器或安装依赖。成果须选择普通文本变更、预览后确认整合，冲突停止、不自动提交。目录隔离不是操作系统沙箱，shell 仍具有当前用户权限。
- **三模板接入向导**：提供本机 MCP、HTTPS MCP、HTTP JSON bridge 三种模板。静态检查只验证配置格式和凭据存在性，不启动程序或联网；确认目标后才进行短生命周期诊断。诊断不自动调用软件动作、知识搜索／阅读或注册启用能力，握手成功不代表业务查询已验证；无法判定的阶段显示 unknown。保存后仍需在连接卡明确连接并逐项确认启用，凭据只使用环境变量引用。

入口、容量、失败恢复及数据路径详见 [项目任务、Git 审阅与知识版本](../project-work.md)、[工作资料工具说明](../workspace-data-tools.md) 和 [本地记忆、知识库与模型选择](../memory-knowledge-models.md)。

## 下载与升级

正式发布后，从 [GitHub v1.1.5 Release](https://github.com/Guyao146/SakuraCode/releases/tag/v1.1.5) 获取 Windows x64 桌面包 `SakuraCode-1.1.5-win-x64.zip`。仓库为 [Guyao146/SakuraCode](https://github.com/Guyao146/SakuraCode)。draft 阶段需先核验附件名称、内置版本、发行说明与 SHA-256，再发布正式 Release；本文不保证下载链接目前已可用。

升级前退出旧版、备份程序及个人资料，核对下载文件 SHA-256 后手动替换程序和使用说明。不要删除 `%LOCALAPPDATA%\SakuraCode\Desktop`、项目 `.sakura` 或自定义会话目录，也不要把独立开发目录的私有 `data` 当作可随程序清理的缓存。工作资料备份不代替源码备份，独立开发目录的执行数据也不自动并入原工作区备份。

源码推送和标签发布不会替换已安装的 EXE。构建仍未签名（unsigned），Windows 可能提示未知发布者；SHA-256 用于核对完整性，不能代替可信发布者签名。已有用户设置和匿名统计偏好继续保留。

## 验收与边界

本次 v1.1.5 本地发布验证已完成：全量 **125 个测试文件、1,579 个用例通过，零失败、零跳过**；源码及 `tests`／`scripts` 严格类型检查通过，Node/Web 资源与 Windows 桌面包重建通过。隔离桌面冒烟通过，包括内嵌 PDF／DOCX 解析、资料备份恢复、连接诊断、独立目录整合及原有桌面流程。测试使用临时工作区、合成资料、假凭据和本机服务，未验证真实第三方平台。GitHub CI 与附件状态以本次标签触发的工作流结果为准。

- **发布前要求**：对最终 v1.1.5 版本运行适用测试与严格类型检查，重建桌面产物；核对内置版本、文档解析器及资源打包、发行附件和 SHA-256，再检查 draft 内容。记录实际命令、结果、失败或跳过项。
- **重点核验范围**：任务真实退出状态／日志与人工验收、失败不重放、Git 差异和 index 不变、知识历史引用与版本冲突、文档来源与超限拒绝、备份新目录恢复、独立 worktree 数据隔离和整合冲突、向导静态检查及确认诊断边界。测试结论应说明临时数据／合成服务范围，不能据此承诺真实第三方服务可用。
- **明确未覆盖的物理交互**：桌面 smoke 使用 `--no-physical-input`，物理键鼠拖动／双击／快捷键、前台屏幕截图及系统中文输入法候选确认未覆盖。原生窗口 API 或页面自动化结果不能替代这些验证。
- **访问与执行边界**：新增管理、预览和下载入口限本机操作员，远端／访客／手机分享不因此获得权限。验收命令和独立目录工具仍可能修改文件或联网；审批与目录分离不构成操作系统沙箱。关闭或断开不能撤销已经发生的外部副作用。
- **数据与恢复边界**：日志、任务报告、备份、补丁、知识原件和独立运行数据均可能含私有内容，分享前须审查；不应默认随源码提交。Git 审阅不是秘密扫描器，子模块内部 dirty 状态不保证可见；多文件整合不是文件系统级原子事务，失败需按保留的恢复记录处理。
- **知识与外部调用边界**：本地解析、预览和版本切换本身不调用模型、不自动上传资料；用户正常发送引用或允许工具读取后，片段仍会进入所选模型请求。向导不安装外部软件，不自动连接或启用能力，诊断成功不等于真实业务已验收。
