# SakuraCode v1.1.4

本次版本加入按工作区管理的外接软件／知识库接口，并提供本地记忆按需检索、独立模型选择和 Windows 桌面保存可靠性改进。旧记忆、知识文件、连接配置以外的用户设置、会话和项目文件不自动迁移或删除。

## 改进

- **外接软件与知识库**：设置 → 集成与连接新增连接管理。复用 MCP stdio／Streamable HTTP，新增 HTTP JSON 桥接 v1 和 `sakuracode/connectors` 适配器接口；提供本机合成桥接示例。保存连接不执行程序或联网；连接目标须确认，发现动作／知识能力后还须逐项启用。外部动作和 `external_knowledge_search`／`external_knowledge_read` 保留原审批门。
- **外部知识范围**：搜索必须选择已配置并显式启用的连接，不广播查询、不整库注入、不自动导入本地知识或记为长期记忆。返回来源／版本使用服务实际提供值，分页有界；检索结果按外部参考资料处理。查询会发送给所选服务，模型调用工具后获得的片段也会发送给当前模型服务。
- **凭据和监听**：连接文件 `.sakura/connectors.json` 只保存非秘密元数据与环境变量名，不能存 Token／Key 明文。远端／访客／手机分享没有连接管理或任意软件调用权限。连接器不安装服务、不改变 Web 监听地址或自动转发项目／账号／聊天。
- **本地记忆优化**：可选全文注入（兼容默认）或 `memory_search` 按需检索；持久去重保留采集来源，已停用记忆和待整理内容不进入检索。工作区 Markdown／TXT 知识库支持来源与版本验证、长行分页及明确引用。
- **智能体独立选模**：主智能体与协作成员可分别查看职责推荐并明确确认。仅改变目标成员后续回合，不覆盖全局模型；运行／排队目标拒绝切换，失效的已固定模型不会静默转向其他提供方。
- **桌面存储可靠性**：修复 Windows `File.Replace` 偶发 Win32 1175 导致账号／设置写入失败的问题。原子替换保留 DACL／属性；锁定、只读或权限不足仍明确失败并保留原文件，不自动重试敏感凭据操作。

## 下载与升级

从 [GitHub v1.1.4 Release](https://github.com/Guyao146/SakuraCode/releases/tag/v1.1.4) 获取 Windows x64 桌面程序或 `SakuraCode-1.1.4-win-x64.zip`。发布自动化会先创建草稿 Release；确认附件、版本、发行说明和 SHA-256 后，再由维护者在 GitHub 发布为正式 Release。

升级前先退出旧版、备份 EXE 并核对下载文件的 SHA-256；仅替换程序和使用说明。不要删除 `%LOCALAPPDATA%\SakuraCode\Desktop`、项目 `.sakura` 或自定义会话目录。源码推送不会替换已安装的 EXE，需要手动升级。构建未签名，Windows 可能提示未知发布者；SHA-256 不代替可信发布者签名。

外接配置首次添加后只保存元数据，不会连接。连接前核对程序路径／目标主机；远端地址须 HTTPS；Token／Key 放在已受信任的进程环境变量，避免命令参数明文。只连接信任的软件，不要发送不适合外传的资料。HTTP v1、MCP 绑定、权限及数据流详见 [外接连接器协议](../external-connectors.md)。

## 验收与边界

- 全量 110 个测试文件、1,415 个用例通过，无失败／跳过；最终界面调整后的 16 个外接接口、远端权限和真实浏览器回归通过；源码及 `tests`／`scripts` 严格类型检查通过。
- 隔离 Windows 桌面重建与端到端冒烟通过：合成 MCP／HTTP、DPAPI 保存与失败回滚、外接连接保存不联网、确认能力、版本化知识检索／阅读、断开移除、重启、工作区切换和退出清理。外接测试使用 loopback 本机服务与临时工作区，不连接真实第三方软件、账号或云知识库。
- **明确未验收的物理交互**：桌面冒烟以 `--no-physical-input` 执行；物理键鼠拖动／快捷键、前台屏幕截图和系统中文输入法候选确认未验证。CDP 测试不能替代这些物理测试。
- HTTP JSON v1 是软件桥接契约，不意味着任意没有 MCP／API 的应用可直接接入。自定义适配器和 MCP 子进程是本机可信代码，不能视作隔离沙箱；断开不能撤销已经到达外部软件的副作用，失败不会自动重放。
- 本次没有部署桥接服务、没有自动上传数据、没有自动迁移／删除用户知识，也没有在本地调用真实模型服务进行推荐或回归。
