# 授权后设置内容向右偏移

## 与官网确认失败区分

账号与余额中已经显示用户名、VIP 和「退出授权」，但卡片右半边及窗口操作按钮看不到，是显示区域问题；这张图本身不表示官网仍在拒绝授权。账号凭据和模型 Key 独立，连接账号后仍需在模型设置明确选择 Key。

## 复现与修复范围

在隔离用户目录启动旧桌面 EXE，以合成公开账号状态显示卡片。正常 1454px 浏览器区域里卡片从 x=398 开始；当嵌入浏览器意外扩大到 2560px 而原生主窗口保持不变时，卡片从 x=951 开始，右半边被主窗口裁切，与报告截图的几何位置一致。

旧容器只在主窗口 resize 时校正浏览器。注入真实浏览器 HWND 尺寸偏移后，等待和焦点返回均不恢复；轻微调整主窗口尺寸后恢复。另一个显式 CDP 视口覆盖也能产生相同截图，但这是独立原因，不能把相似截图当作使用了 CDP 的证据。

修复在应用重新激活、托盘返回工作区及既有 500ms 运行监控中复查浏览器边界。仅实际位置或尺寸不一致时调用原生尺寸校正，不新增定时器、网络查询或反复布局。最小化及退出时不操作浏览器。正常情况下不改变焦点、光标、账号凭据、模型选择及布局偏好。

这验证了尺寸漂移的可复现机制和恢复能力，**未在真实账号流程中捕获最初触发漂移的 Windows/Chromium 事件**。不修改官网 Origin、Referer、同意、PKCE 或换码逻辑。

## 旧版临时恢复

轻微拖动主窗口边缘使其变宽或变窄，再回到原尺寸。若授权仅保存在内存，退出应用将需要重新授权，因此优先调整窗口，不要先退出授权、清空浏览器数据或删除设置。内置页面由 EXE 提供，修改开发目录不会更新已安装的旧 EXE。

## 验证

- `tests/web-account-layout-client.test.ts`：在真实隔离 Chromium 中完成合成 PKCE 登录，检查授权、刷新、重载、退出及重新授权前后的布局，覆盖日夜主题及 320–2560px 宽度；账号状态和凭据不使用真实数据。
- `scripts/desktop-smoke.ts`：向独立测试桌面的浏览器 HWND 注入 2560px 尺寸漂移，要求不改变主窗口尺寸即可恢复真实视口，并检查账号卡片、余额及按钮；原生桌面不使用手机 CDP 尺寸覆盖。
- 本次独立证据位于 `D:\VSProject\SakuraCode\tmp\account-authorization-layout\`；此前优化验收证据保留在原目录，不被新阶段覆盖。

原生公开账号状态注入只验证显示；合成 PKCE 测试只验证本地流程。它们不等于再次用真实账号确认官网授权成功。物理鼠标输入、IME 与多 DPI 显示器行为仍需对应的交互验收。
