# 桌面对话与登录体验

## 授权跨启动保存

桌面版默认勾选「使用 Windows 加密记住登录，下次启动自动恢复」。独立客户端 access/refresh token 与所选模型 Key 仍由启动器使用当前用户 DPAPI 加密，保存到 `%LOCALAPPDATA%\SakuraCode\Desktop\sakuraapi.json`。原子写入得到私有管道确认后才声明已保存。

已连接的账号可以直接开启保存，无需退出或再次官网同意；取消保存只删除密文，当前连接继续，重启后需授权。保存／移除失败保留原状态并提示错误。没有安全保存回调的普通 Web 继续只在内存保留授权，远端操作员和访客不能访问本机账号。真实账号不用于自动化测试。

有效授权在启动后同步，不重复打开同意页；撤销、失效或连续 120 小时闲置仍需重新授权，不能绕过官网政策。关闭旧版本会丢失未保存的内存授权；升级前如有任务需先完成，切勿强杀或删除用户数据。

## 专家共享上下文，归档日志仍独立

默认专家为架构师、实现者、审查者，与主智能体读取**同一个主会话的已提交上下文**。用户任务在模型上下文中只出现一次，成员完成一个模型／工具步骤后才提交带来源的协作记录；其他成员下一步读取它。并行请求已经发出时不会强行重启请求或插入半个工具调用，也不保证首轮主回答等待全部专家；「汇总专家结论」用于团队统一答复。

专家仍有各自的原始归档日志与附件副本；主会话同时保存可共享的成员证据，刷新后能重放专家卡。每步的 `expert-context` 记录保存主上下文 ID、已提交序号与当前用户任务边界，慢专家不会误读下一条排队用户任务。共享记录不会造成主智能体待执行的工具调用；主工具调用与结果始终成对相邻。会话切换／工作区重挂仍清理花名册，普通独立子智能体维持原隔离行为。

新记录在创建事件中明确保存 `role: sub` 和专家标记；流式会话摘要只增加该有限标记，不加载全文或修改旧日志。普通会话和协作概览排除已明确标记的专家记录，工作台「专家内部记录」保留只读查看入口，重启后也可读取。仍兼容当前进程中旧记录的真实专家属主，不按「架构师」名称猜测，不批量改写或删除过去未标记的记录。

## 一行折叠

- 超过 600 字符或 10 行的任务／回答默认折叠；专家与独立会话阅读器默认整条折叠。
- 折叠行显示最新非空输出行的最后 160 字符，持续跟随流式输出。错误或中断摘要明确标注，不将旧成功当成当前结果。
- 点击或聚焦后按 Enter 展开全文；聊天上方可批量收起长对话或展开对话。复制仍取全文，附件、工具卡和历史保留。
- 手动选择在本页的回合结束／重连历史同步中保留，刷新后回到默认折叠；选择缓存最多 400 条，不保存文本或凭据到浏览器存储。
- 主对话磁盘重放不移除实时专家卡片，也不使仍在输出的专家失去绑定。成功变更可从工作台自动展开对应专家工具卡。
- 专家整卡展开／收起使用相同标题行高度和内边距，预留箭头宽度，不因正文显示改变第一行的对齐。侧栏恢复入口与展开侧栏的品牌标识共享相同图标尺寸、圆角、边框及顶部位置。

折叠是显示行为，**不是 token 上下文压缩**，不会调用模型、删除历史或改变可见模型上下文。实际上下文压缩沿用输入区现有入口和确认／阈值。

## 托盘与顶部进度

最小化按钮、系统最小化命令和托盘「收起到托盘」隐藏窗口，后台任务继续。双击托盘、选择「打开工作区」或再次启动恢复同一窗口与浏览器、草稿和最大化状态。不在浏览器挂载后切换 `ShowInTaskbar`，避免原生句柄重建销毁 Chromium。关闭／Alt+F4／托盘退出仍执行完整后台退出，不把关闭悄悄改成隐藏。

任务进度位于工作台标题下、协作／变更标签之前，两种面板均可见。长任务列表有独立高度上限与滚动；进度由真实 `todo_write` 更新，不推测百分比。

## 会话状态、单条提示与长期记忆

- 左侧每个会话前置状态标识，并有可访问名称与文字：未开始、未完成、已完成、失败、已中断；当前运行与审批／问题／计划／重试等待来自实时智能体／待处理请求。磁盘里的未完成会话不被标成仍在运行，列表继续使用有限摘要，不为每个状态读全文。
- 专家启用／关闭／操作失败更新同一条可关闭状态提示，不追加到聊天记录，也不将提示送进模型。
- 专家模式的自动待整理候选仅取原始用户要求，过滤引用展开与常见凭据；整理时只提取明确的长期调整方向。失败或取消后的用户要求仍可保留，成员回复／猜测／工具日志不会被采集。专家汇总与成员通信有明确非用户来源。
- 专家与其委派成员不能使用内置 `memory_write` 或直接 `write/edit` 改工作区记忆；用户仍可在设置中手动编辑。已有记忆与旧候选不被批量改写或删除。全权限 shell／第三方插件不是隔离沙箱，不能把这些过滤宣称为任意命令的文件写入防护或完整 DLP。

## 按真实可见区域布局

原生启动器在尺寸／位置／DPI／激活与恢复时读取实际 `GetClientRect`，比较浏览器外框与客户区，修复真实漂移。私有管道仅传宽高、DPI 与递增版本，不传账号、地址或 HWND；页面按该尺寸与实际 DPR、visual viewport 的较小可见区域布局。异常时可请求原地 reflow，不重挂 Chromium、不刷新或重放对话，不改草稿、附件或选区。

页面 resize／focus／恢复使用合并动画帧与一次 220ms 后复核；有尺寸变化才用 180ms 轻量过渡，系统「减少动态效果」时停用。原生尺寸／激活事件另合并一次 80ms 客户区复核；既有 500ms 监测只修复漂移，无变化不不断重绘。启动就绪与保留旧画面的切换机制见 [启动、切换与工具图标](desktop-motion-icons.md)。

## 每轮 token 与耗时

主回答下方显示本轮 token 与总耗时；折叠回答仍保持一行，统计独立显示。专家卡展开可看成员统计。有团队时主回答先显示「专家处理中」，全部本轮成员与有归属的 `send_message`／委派回合结束后原位更新「整轮（含专家）」；后到统计只更新对应用户序号。

每次模型尝试只取最终累计 usage 帧，重试失败尝试也计入；缺字段按实际请求（含工具定义）与输出／思考／调用文本估算，标明「接口报告」「估算」或混合。它不是账单。总耗时含模型、工具、审批与重试等待，不含本轮启动前的排队时间；并行成员按最早启动到最晚结束计算，不相加耗时。失败／中断也保存统计。

新统计追加 `turn-summary` 笔记，历史／刷新／分支仍可还原。旧日志不改写，只从时间戳和现有流记录读时推算，并明确标记耗时 ≈；旧日志缺少真实完整请求时，输入 token 估算精度更低。没有完成标记的旧工具回合不伪称已结束。
