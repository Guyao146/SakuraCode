# 扫码／链接连接工作区

电脑主动连接你部署的 HTTPS 中转，手机通过二维码或复制链接访问。因此手机可以使用移动网络，无须与电脑处于同一 Wi-Fi，也不需要开放电脑的公网端口。

## 安全边界

- 默认只读；每个设备的“发送任务／停止当前轮”权限必须由本机操作员明确授予，可随时降权或撤销。
- 手机不能审批工具、回答电脑上的审批对话框、修改账号／Key／模型设置、切换工作区、删除／回滚会话或访问任意文件／HTTP 接口。
- 手机发送的任务依然通过当前 Agent、专家协作与审批策略。不要向不可信设备授予控制：控制者可以向 Agent 提交任务。
- 邀请是高熵短期秘密，位于 URL fragment，打开手机页面后立即从地址栏移除；默认 10 分钟内仅可使用一次。截图或复制链接仍会包含邀请，请勿公开传播。
- 分享默认 2 小时后失效。点击“停止”、引擎退出或工作区切换／重挂会撤销访问；本机 Agent 不因停止分享而中断。
- 数据仅在明确开始分享后发送。中转使用内存中的有界临时房间，不将工作区历史写盘；重启后邀请与设备会话失效。
- **不是端到端加密**。电脑／手机通过 HTTPS 与可信自建中转通信；中转运营者能够看到传输的工作区内容。请只使用你信任的服务。
- 手机收到的是特定工作区投影，不是完整桌面 state/SSE：账号、API Key、微信绑定信息、最近其他工作区、系统提示、工具原始参数／输出、图片和附件路径不发送。可见聊天与专家正文仍可能含业务或其他敏感信息；文本清理不保证消除所有秘密。

## 1. 构建中转

在已有仓库中安装依赖并构建（不需要额外第三方隧道）：

```sh
npm ci
npm run relay:build
```

输出 `build-relay/workspace-relay.mjs`，包含手机页面。可把这个单文件复制到安装 Node 20+ 的服务器运行；建议 Node 24。

生成 32 字节随机注册凭据：

```sh
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))"
```

该凭据只用于电脑注册分享房间，不是手机访问令牌。不要提交到仓库、放进命令日志、二维码或 URL。

## 2. 运行并配置 HTTPS

服务器示例（替换域名和凭据；凭据建议从进程管理器的受保护环境配置注入）：

```sh
export SAKURA_RELAY_REGISTRATION_TOKEN='<随机注册凭据>'
export SAKURA_RELAY_PUBLIC_ORIGIN='https://relay.example.com'
export SAKURA_RELAY_HOST='127.0.0.1'
export SAKURA_RELAY_PORT='8787'
node workspace-relay.mjs
```

开发时可用 `npm run relay`。仅本机测试允许 `http://127.0.0.1:<port>`；生产公网 origin 必须为 HTTPS，不含路径、查询、账号或密码。

使用 `deploy/workspace-relay/nginx.conf` 作为反向代理模板，并配置你已有域名／证书。代理必须保留精确 Host（非标准端口也要保留），关闭 SSE 缓冲和缓存，允许 256 KiB 请求体及至少 60 秒读取超时。服务不使用 `X-Forwarded-*` 跳过 Host／Origin 防护。

Docker 模板：

```sh
docker build -f deploy/workspace-relay/Dockerfile -t sakuracode-workspace-relay .
docker run --rm --read-only --cap-drop=ALL --security-opt=no-new-privileges \
  -p 127.0.0.1:8787:8787 \
  -e SAKURA_RELAY_PUBLIC_ORIGIN='https://relay.example.com' \
  -e SAKURA_RELAY_REGISTRATION_TOKEN \
  sakuracode-workspace-relay
```

若代理就在宿主机，Docker 对外端口仍仅绑定回环；不要将 8787 明文暴露到公网。上述模板不自动申请证书、不改 DNS／防火墙、不部署任何真实服务。

## 3. 电脑生成二维码

1. 侧栏底部点击 **连接工作区**，或在设置 → 集成与连接进入。
2. 输入中转 HTTPS origin 和注册凭据。
3. 确认当前工作区数据将经过此中转，再点击 **开始连接**。
4. 出现“等待手机连接”后，用手机扫码，或 **复制链接** 到手机浏览器打开。
5. 手机为设备命名后连接。电脑会显示已认证设备、只读／控制权限和在线状态。
6. 需要另一台设备时点击 **重新生成邀请**；旧邀请立即失效，但已授权设备保持连接。
7. 点击 **断开设备** 撤销该设备，或 **停止** 撤销整个分享。

注册凭据只用于当前进程，页面成功连接或关闭弹窗后清空输入，不写入桌面设置。可预设工作区中转地址，并从环境变量读取凭据：

```yaml
workspaceSharing:
  relayOrigin: https://relay.example.com
  registrationTokenEnv: SAKURA_RELAY_REGISTRATION_TOKEN
```

即使配置存在，也不会自动开始分享。二维码是中转地址，不是 `localhost` 链接；没有部署中转时无法保证手机流量访问。

## 断线与重复提交

- 电脑离线时手机显示离线且不能发送任务。恢复的是只读连接，不会自动重发先前任务。
- 手机历史选择只读，不改变电脑主会话。
- 每次任务带独立操作 ID；在最近 1,024 次操作的去重窗口内，同设备同 ID 的重复提交只返回原结果，不再次投递；不同内容复用同 ID 被拒绝。不要在窗口淘汰后复用旧操作 ID。
- 请求超时可能是“结果未知”而不是“没有提交”。请先查看会话确认，再明确决定是否重试。
- 非活动设备可以撤销；断网不代表权限自动永久撤销。停止分享是最终撤销入口。

## 限额与验证

中转默认最多 32 个临时房间、每房间 8 个设备、32 个待处理请求，消息帧上限 256 KiB，历史最多 160 项／120,000 字符，任务最多 8,000 字符。超过限额返回明确错误，不无限扩张队列或冒充完整历史。

自动化回归使用本机中转、临时 HOME／工作区与假凭据：二维码／链接一致、单次邀请、默认只读、授权／降权／停止、操作去重、离线恢复、工作区 epoch、私有数据隔离和手机窄屏布局。真实公网部署仍需服务器和域名，并应单独做 HTTPS／代理／网络可达性验收。
